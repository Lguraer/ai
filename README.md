## 一、这是什么

这不是一份「AI 新闻汇总」，也不是「工具推荐清单」。

它是一份**结构化的知识索引**：每条内容保留原始链接与互动数据，便于回溯原文；每个主题附有一份人工撰写的知识骨架（概念 → 关键决策 → 常见误区 → 学习顺序），用于建立整体框架。

**两者分工明确**：骨架告诉你「该学什么、按什么顺序」，条目告诉你「具体去哪看」。

## 三、三条阅读路径

### 路径 A：从零建立框架（约 3 小时）

```
00 学习路线 → 通读一份带「哪里会翻车」标注的路线图，只建地图不执行
01 提示与上下文工程 → 读「核心知识骨架」+ 四要素
05 评测与可靠性 → 读「先做错误分析」一节
```

**为什么先读评测**：没有评测能力，前面学的方法都无法验证效果，只能靠感觉。这是新手最容易被跳过、也最该提前补的一环。

### 路径 B：要做产品，卡在效果上（约 2 小时）

```
05 评测 → 03 RAG（分层评测：检索层 vs 生成层）→ 01 上下文预算 → 02 Agent 终止条件
```

顺序有讲究：先能测，再优化。跳过评测直接调提示词，是效果反复横跳的主因。

### 路径 C：用 AI 写代码，想提高可靠性（约 1.5 小时）

```
06 工程实践 → 05 评测（结构化输出与回归测试）→ 07 安全（最小权限与人工确认）
```

核心结论在 06：AI 编程的瓶颈已从「写」转移到「审」，验收基础设施（测试、类型、lint、CI）决定你能用多激进的方式。

## 四、跨主题的五个共识

这 359 条内容里，反复出现、且来自不同作者独立得出的判断：

**1. 瓶颈普遍不在模型**
提示质量、上下文结构、检索准确率、工具设计，这些工程环节对结果的影响，通常大于换一个更强的模型。

**2. 上下文不是越多越好**
无关内容会稀释注意力，长上下文推高延迟与成本。有实测指出，给 Agent 硬加向量库反而降低准确率。

**3. 评测是分水岭**
「会调 API」与「能做产品」的差别，在于有没有能力判断改动是否有效。这一条在所有路线图中都被标注为「最多人跳过」。

**4. 多 Agent 不是默认更优**
协调开销随数量上升，信息在传递中损失。先证明单 Agent 做不到，再考虑拆分。

**5. 提示注入没有根治方案**
模型无法在同一个通道里区分「数据」与「指令」。只能靠架构缓解：最小权限、人工确认、输出校验、沙箱隔离。

## 五、筛选标准（摘要）

**纳入**：正文含 ≥2 个技术概念；推文 ≥110 字符；YouTube ≥5 分钟且 ≥800 播放；具备可迁移的方法、原理或判断标准。

**排除**：八卦、社会新闻、致富、招聘、娱乐、营销话术、标题党（`in just N minutes`、`without coding`、`goldmine`、`🤯` 等）、非中英文语种。

**漏斗**：Twitter 457 → 257（56%）；YouTube 309 → 102（33%）。共排除 407 条，其中播放量过低 118 条、标题党与营销 106 条、技术密度低 79 条、短视频 63 条、无技术词 20 条。

完整规则与关键词见 [`数据/采集与筛选说明.md`](数据/采集与筛选说明.md)。

## 六、使用前必须知道的四件事

**1. 条目中的数字与结论来自原作者，本文档未逐条核验。** 引用前请打开原始链接确认。部分推文含产品宣传口径，需自行判断。

**2. 分类基于关键词正则，跨主题内容只归入主要一类。** 例如「Agent 的 RAG 评测」会归入 02 或 03，不会同时出现在两处。需要交叉查找时用 `数据/全量清单.md`。

**3. 时效性分层**：原理层（Transformer、注意力、RAG 架构、评测方法论）可管 2–3 年；工具层（具体框架、模型版本、产品功能）半年即过期。文档中两者混排，阅读时需自行区分。

**4. 这是索引，不是存档。** 内容可能被原作者删除或修改。重要内容建议自行留存。

## 七、如何更新

采集与生成脚本位于 `E:/WBAi/tools/`：

| 文件 | 作用 |
|---|---|
| `kb_build.py` | 筛选 + 分类，读 `ai_kb_raw.json`，输出 `ai_kb_filtered.json` |
| `kb_frames.py` | 各分类的知识骨架文本（人工撰写部分） |
| `kb_gen.py` | 组装 Markdown，输出到本目录 |

**增量更新方式**：修改 `kb_build.py` 顶部的关键词列表 → 重新抓取 → 依次执行 `kb_build.py`、`kb_gen.py`。

注意：`kb_gen.py` 会覆盖本目录下的分类文档，但**不会覆盖本 README**。若在 README 中手工添加了笔记，请自行备份。
