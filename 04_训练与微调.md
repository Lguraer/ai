## 一、这类知识解决什么问题

这个领域的知识分两层：**要不要微调**（决策层）与**怎么微调**（执行层）。多数人卡在决策层——花两周微调出一个模型，效果不如改三行提示词。

决策的判断依据是：如果问题是「模型不知道某个事实」，用 RAG；如果是「模型不符合某种输出风格或格式」，用提示 + few-shot；如果是「模型在特定任务上系统性表现差，且有几百到几千条高质量样本」，才考虑微调。

执行层的核心是参数高效微调（PEFT）：LoRA 冻结原模型，只训练低秩矩阵；QLoRA 再把基座量化到 4bit，让消费级显卡也能跑。

## 二、核心知识骨架

**LoRA 的机制**　冻结基座权重，在旁路训练两个小矩阵 A（降维）与 B（升维），推理时把 BA 加回原权重。可训练参数通常只有原模型的 0.1%–1%，显存需求大幅下降。

**量化**　把权重从 FP16 压到 INT8/INT4。QLoRA 用 4bit 量化基座 + LoRA 训练，单张 24G 显卡可微调 7B–13B 模型。量化会带来精度损失，但在多数任务上可接受。

**蒸馏**　用大模型的输出训练小模型。适合「能力已经验证、需要降本」的场景，不适合「探索新能力」。

**推理优化**　量化（AWQ/GGUF）、批处理、KV cache、vLLM/TGI 等推理引擎。这部分对成本的影响常常大于模型选择本身。

**删除权重的研究**　近期有研究发现，删除部分权重（deletion tuning）也能让模型学到新技能，这挑战了「必须调整参数」的直觉，但离生产可用还有距离。

## 三、常见误区

- **数据质量不行就开训**。几百条脏数据的微调结果，通常不如零样本提示。
- **用微调灌知识**。知识会过期，权重里的知识无法更新；RAG 可以。
- **忽略灾难性遗忘**。微调后模型在通用任务上退化，需要混合通用数据一起训。
- **只看训练 loss**。要看留出集上的任务指标。

#### 9. LoRA vs QLoRA Fine-tuning without retraining everything
`@GauravGoyalAI` · ♥ 38 · 收藏 11 · 2026-09-22 · [原文](https://x.com/GauravGoyalAI/status/2102259043859656745)

> LoRA vs QLoRA Fine-tuning without retraining everything
>
> Fine-tuning a large LLM can be expensive.
>
> So instead of updating every model weight, we can use LoRA.
>
> 🔹 Full Fine-Tuning → Update all weights
> 🔹 LoRA → Freeze the base model + train a small adapter
> 🔹 QLoRA → Quantize the base model + train the LoRA adapter
>
> The key idea:
>
> LoRA → reduces what you train.
> QLoRA → reduces what you store + what you train.
>
> Think of it as:
>
> «Same base model. Smaller update. Lower memory.»
>
> QLoRA can make fine-tuning large models much more accessible when GPU memory is limited.
>
> 📌 Save this if you're learning LLM fine-tuning.

## 五、推荐学习顺序

1. 先确认提示工程 + RAG 已经试过且不够用
2. 整理 200–1000 条高质量样本（输入-输出对），划出验证集
3. 用 LoRA 跑一版，对比基座模型在同一验证集上的表现
4. 有效再考虑 QLoRA 扩大规模、或用蒸馏降本
5. 上线前做推理优化（量化、批处理、引擎选型）
